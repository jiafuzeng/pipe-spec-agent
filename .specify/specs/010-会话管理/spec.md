# Feature Specification: 会话管理

**Feature Branch**: `010-会话管理`

**Created**: 2026-11-27

**Status**: Draft

**Input**: User description: "会话管理。web 页面左侧要实现历史会话，可以在历史会话中继续聊天。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从左侧打开历史会话并继续聊 (Priority: P1)

演示人员回到规程问答页，在页面左侧看到以前的会话，点开其中一条，能看到这段对话里已经发生的提问和回答，并再发一条消息。新消息留在这一段对话里，不会跑到别的会话。

**Why this priority**: 没有历史列表，关掉页面或换一段对话之后就找不到刚才的问答。能接着聊，现场演示才不用从头再问。

**Independent Test**: 先完成两段各含一条提问和回答的会话。回到问答页，左侧能看到这两段。打开其中一段，只出现该段的提问和回答；再发一条消息后，这条新消息仍只属于这一段。

**Acceptance Scenarios**:

1. **Given** 工作台里已有至少两段发生过问答的会话，**When** 演示人员打开规程问答页，**Then** 页面左侧列出这些历史会话，且能凭每条上的最近提问把它们区分开。
2. **Given** 左侧列出多段历史会话，**When** 演示人员点开其中一段，**Then** 主区域只显示这一段已经发生的提问和回答，不显示其他会话的内容。
3. **Given** 已打开一段历史会话，**When** 演示人员再发送一条消息，**Then** 回答出现在这一段里；左侧这一条改为显示最新的提问，其他会话的内容不变。

---

### User Story 2 - 新开一段而不丢掉旧会话 (Priority: P2)

演示人员正在看一段旧对话时，可以新开一段。新的一段从空白开始。刚才那段仍留在左侧，之后还能点回去继续。

**Why this priority**: 继续旧对话之外，现场还要能换一道新题。新题不能把旧对话盖掉。

**Independent Test**: 打开一段已有提问的历史会话，再新开一段并只在新段里提一个不同的问题。左侧同时还有旧段和新段；点回旧段时仍是原来的提问和回答。

**Acceptance Scenarios**:

1. **Given** 当前打开的是一段已有内容的会话，**When** 演示人员新开一段，**Then** 主区域没有上一段的提问和回答，可以立即输入新问题。
2. **Given** 新段里已经发出一条消息，**When** 演示人员从左侧点回上一段，**Then** 上一段的原有内容还在，新段的消息不混进来。

---

### User Story 3 - 重新打开工作台后仍能接着聊 (Priority: P3)

演示人员关掉问答页或整个工作台后再打开。左侧历史会话还在，上次正在看的那段可以继续，不必重新找。

**Why this priority**: 历史会话如果只活在当前这一次打开里，刷新之后就无法继续聊天。

**Independent Test**: 在一段会话里完成一问一答后关闭问答页，再打开。左侧仍有这段；进入后能看到刚才的问答，并可以再发一条。

**Acceptance Scenarios**:

1. **Given** 一段会话里已有提问和回答，**When** 演示人员关闭后再打开规程问答页，**Then** 左侧仍列出这段会话。
2. **Given** 关闭前正在看某一段，**When** 再次打开问答页，**Then** 直接进入这一段，并显示关闭前已经发生的提问和回答。
3. **Given** 再次进入的是上次那段，**When** 演示人员继续发送消息，**Then** 新消息追加在这段已有内容之后。

---

### Edge Cases

- 还没有任何会话时，左侧说明还没有历史会话，并仍能开始第一段对话。
- 最近一条提问很长时，左侧只显示能认出这段对话的开头，不把整段聊天铺满左侧。
- 多段会话的最近提问文字相同时，左侧同时显示最近活动时间，避免只能靠猜。
- 历史会话很多时，左侧仍能滚动查看，最近有活动的排在最上面。
- 点开的会话读不出来时，说明这段暂时打不开，并保持左侧列表；不改显示另一段的内容。
- 一段会话正在等待回答时，不把演示人员带到另一段，避免答完后写错地方。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 规程问答页的左侧必须列出本工作台已有的历史会话。
- **FR-002**: 每一条历史会话必须显示该段最近一次用户提问，以及该段最近一次活动的时间。列表按最近活动从新到旧排列。
- **FR-003**: 演示人员点开一条历史会话后，主区域必须只呈现这一段已经发生的提问和回答。
- **FR-004**: 在已打开的历史会话中发送新消息时，新的提问和随后的回答必须追加到这一段，不得写入其他会话。
- **FR-005**: 一段会话有了新的用户提问后，左侧对应条目必须改为这条最新提问，并按最近活动重新排列。
- **FR-006**: 演示人员必须能新开一段会话。新段在发出第一条消息前没有历史内容；已有会话仍留在左侧。
- **FR-007**: 关闭问答页或重新打开工作台后，历史会话必须仍可列出，并且可以打开后继续聊天。
- **FR-008**: 重新打开问答页时，必须进入上次正在看的那段会话；若那段已经不存在，则停留在空白的新对话，并保留其余历史会话。
- **FR-009**: 左侧历史会话占用问答页左侧时，导入文档和评测入口必须仍然可达。
- **FR-010**: 一段会话无法打开时，必须说明暂时打不开，且不得把其他会话的内容显示成这一段。
- **FR-011**: 没有任何历史会话时，必须能开始第一段对话，并在发出第一条消息后出现在左侧。

### Key Entities

- **会话**: 一段连续的规程问答。有自己的提问、回答和最近活动时间。
- **历史会话条目**: 左侧列表中的一条，指向一个会话，展示最近一次用户提问和最近活动时间。
- **聊天记录**: 某一段会话里按发生顺序排列的提问和回答。只属于这一段。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已有两段问答时，打开规程问答页后，演示人员不需要回忆或重输，就能在左侧找到这两段。
- **SC-002**: 点开一段历史会话后，一次打开就能看到该段已有的提问和回答；抽查时不出现其他会话的句子。
- **SC-003**: 在历史会话中再发一条消息后，该消息和它的回答只出现在这一段；回到另一段时看不到它。
- **SC-004**: 关闭并重新打开问答页后，上次正在看的会话仍可继续，且关闭前的提问和回答还在。
- **SC-005**: 连续新开三段并各发一条不同的提问后，左侧这三条都能按最近提问区分，并能分别点回去。

## Assumptions

- 使用者是这一台工作台上的演示人员。会话保存在这台工作台，不区分账号，也不在多台设备之间同步。
- 本变更把该模块的范围定为会话管理。长期记住工程参数、跨会话沿用和把记忆当作规程依据，不在本规格内。
- 「继续聊天」指重新看到这一段已有的提问和回答，并能够再发消息；新消息追加在同一段后面。
- 左侧条目用最近一次用户提问识别会话。提问超过一行时只保留开头。最近提问文字相同时，用最近活动时间区分。
- 列表按最近活动从新到旧。本规格不包含重命名、删除或搜索历史会话。
- 问答页左侧用来放历史会话。工作台原有的导入文档和评测入口仍然保留，不因本列表被去掉。
- 一段会话正在等待回答时，先等这段结束，再切换到其他会话。
- 规程是否有依据、计算是否给出指数，仍按工作台既有问答规则。本规格只规定会话如何被找到和接着使用。
