# Quickstart: 会话管理

先有会失败的测试，再改列表和问答页。不调用真实模型。

## 准备

在仓库根目录使用现有虚拟环境。测试自己创建临时业务库，不写 `data/agent/app.sqlite`。

## 1. 列表顺序与单段隔离

在 `tests/test_sessions.py` 增加并先看到失败：

- 两段会话各有一条不同的用户提问。较早创建的那段后来又有一条更新的提问时，`GET /api/v1/sessions` 把它排在前面。
- 每条包含 `last_message` 和 `last_activity_at`，且 `last_message` 是该段最近一次提问。
- 没有提问的会话不在列表中。
- `GET /api/v1/sessions/{sid}` 的 `messages` 只有该段提问，顺序从早到晚，不受 30 条上限截断。

实现 `app/agent/store.py` 的列表和单段读取，直到：

```bash
.venv/bin/python -m unittest tests.test_sessions -v
```

通过。

## 2. 问答页左侧

打开 `http://127.0.0.1:5173/` 的规程问答：

- 历史会话在问答区域左侧，一列向下排列，最近活动在上。
- 主导航里的导入文档、RAG 评测、Agent 评测仍可进入。
- 点开一段只看到该段的提问和回答。再发一条后，左侧该条变成新提问，另一段不变。
- 新开一段时主区域是空白。发出一条不同的提问后，点回旧段仍是旧内容。
- 刷新页面后仍进入刷新前那段，并能再发一条。
- 等待回答时，其他会话和新会话不可点。

## 3. 打不开的会话

把上次打开的会话号改成列表里没有的值后刷新。页面停留在空白新对话，左侧其余会话仍在，主区域没有另一段的句子。
