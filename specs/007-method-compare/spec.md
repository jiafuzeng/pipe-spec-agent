# Feature Specification: 检测方法对比与检测方案

**Feature Branch**: `007-method-compare`

**Created**: 2026-11-27

**Status**: Implemented

**Input**: User description: "按 Spec Kit 继续开发管道规程工作台。当前缺口是把多种检测方法做成有结论的对比，并在条件不足时先追问再给检测方案。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按条款对比检测方法 (Priority: P1)

演示人员询问 CCTV、QV、声纳等检测方法的术语或适用条件差异，并要求给出选择结论。
系统只根据检索到的规程条款分方法说明，并给出不超出这些条款的结论。

**Why this priority**: 九题里的术语比较和多方法比较是现场必答题，目前回答只是条款摘录，没有按方法分开，也没有选择结论。

**Independent Test**: 给出同时点名至少两种检测方法、并要求比较或说明差异的问题。检索有对应条款时，回答按方法分开、每段带条款号，并有一段选择结论；检索为空时使用固定拒答。全程不出现指数或等级。

**Acceptance Scenarios**:

1. **Given** 已审核条款中分别有 CCTV、QV、声纳的定义或适用条件，**When** 用户询问这三种方式的术语以及适用条件有何差异，**Then** 三种方法分开书写，各自只引用命中的条款，选择结论不另造规程没有的指标。
2. **Given** 用户要求从管径与水位、可识别缺陷、效率与安全、现场配合几个方面对比 CCTV、QV、声纳、人员进入和潜水，并给出选择结论，**When** 系统作答，**Then** 回答覆盖用户点名的方法；没有命中条款的方法明确写未检索到，不编造定义；文末有选择结论。
3. **Given** 检索没有命中任何条款，**When** 用户仍要求比较检测方法，**Then** 回答为固定拒答，不输出对比表或推荐。

---

### User Story 2 - 条件不足时先追问检测方案 (Priority: P2)

演示人员描述一条管道的现场情况，并要求给出检测方案、顺序、安全措施和依据。
系统先列出已经听懂的条件，以及还会改变方法是否适用的缺失项；对已经违反规程
「应 / 不得 / 不宜」的方法直接说明不能采用。

**Why this priority**: 方案题是九题中的综合题。缺条件就给推荐，或把不满足水位、管径限制的方法说成可以采用，都会违反验收。

**Independent Test**: 用一条写明管径、水位、积泥、道路和不能停水，但没写流速、管段长度、积泥是否埋没探头、有无竣工资料的方案题。回答同时含已知条件、缺失项，以及由条款原文支撑的「因此不能采用」。缺失项未确认前不给最终推荐。

**Acceptance Scenarios**:

1. **Given** 用户给出 DN800、水位约 60%、积泥较厚、次干道、不能停水，并要求检测方案，**When** 检索条款写明某方法的水位上限或最小管径，且用户条件不满足该原文，**Then** 回答引用该条款，写明因此不能采用该方法，并列出仍缺失的关键条件。
2. **Given** 同一方案题但检索为空，**When** 系统作答，**Then** 使用固定拒答，不根据常识列出检测方法。
3. **Given** 用户条件满足条款中的数值界限，**When** 系统对照，**Then** 不把该方法写成违反条款。

---

### User Story 3 - 解释禁止性结论与检查顺序 (Priority: P3)

演示人员询问声纳为何不能单独判定结构性缺陷，以及检查井检测应在管道检测之前还是之后。

**Why this priority**: 该题要求明确结论，但不能把模型记忆写成规程。结论必须能在检索原文里找到对应表述。

**Independent Test**: 提问同时包含「为何不能」和检查井先后。原文写明限制和「之前」时，回答复述这两点并带条款号；原文没有「之前」或「不能」时，不自行断言。

**Acceptance Scenarios**:

1. **Given** 条款原文写明声纳不能单独作为结构性缺陷的最终依据，**When** 用户询问为何不能单独判定，**Then** 回答引用该条款，不补充规程外理由。
2. **Given** 条款原文写明检查井检测在管道检测之前，**When** 用户询问先后，**Then** 回答写明在之前并引用该条款。
3. **Given** 检索为空，**When** 用户提出上述问题，**Then** 使用固定拒答。

---

### Edge Cases

- 用户点名的某种方法没有命中条款时，该方法下写明未检索到，其他方法仍可作答。
- 同一条款同时提到两种方法时，两种方法的说明都可以引用该条款。
- 方案题里用户没有写水位或管径时，不做数值对照，只列出已知条件和缺失项。
- 条款用「管径的 1/2」而不是百分数时，仍与用户给出的水位百分数对照。
- 比较题里如果夹有计算意图（例如同时要求画曲线），计算仍按已有追问规则，不在本功能里心算指数。
- 条款原文没有出现的百分数、管径下限或方法名称，不得写进「因此不能采用」。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在用户要求比较或说明检测方法差异时，按用户点名的方法分段作答。
- **FR-002**: 每个方法段落 MUST 只包含检索命中的条款号和原文，MUST NOT 编造定义、适用条件或评价指标。
- **FR-003**: 有检索证据的比较回答 MUST 以一段选择结论结束；该结论 MUST NOT 把规程没有写的建议说成强制要求。
- **FR-004**: 比较或方案问题在检索为空时 MUST 使用章程中的固定拒答，且 MUST NOT 调用指数计算或绘图。
- **FR-005**: 检测方案回答 MUST 分开列出已知条件和缺失条件。缺失项至少包括：积泥是否埋没探头、流速、管段长度、有无竣工资料（用户原文已经给出的除外）。
- **FR-006**: 当用户给出的水位或管径与某条检索原文中的界限冲突时，系统 MUST 引用该条款并写明因此不能采用该方法。
- **FR-007**: 关键缺失条件尚未确认时，系统 MUST NOT 给出最终检测方法推荐。
- **FR-008**: 解释「不能」或检查先后时，系统 MUST 只在检索原文含有对应表述时给出肯定结论。
- **FR-009**: 上述回答 MUST 让用户看见本轮做了检索，并带上被引用条款。

### Key Entities

- **方法说明**: 一种检测方法在本轮回答中的名称、命中的条款号和原文摘录。
- **方案核对**: 用户已经说明的现场条件、仍缺失的关键条件，以及与条款界限冲突的方法。
- **条款证据**: 条款号、原文摘录，以及它支持的是定义、限制还是顺序。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 点名两种及以上检测方法的比较题，在有条款命中时，100% 的验收回答按方法分段并带条款号。
- **SC-002**: 检索为空的比较题和方案题，100% 使用固定拒答，且不出现指数、等级或曲线。
- **SC-003**: 水位或管径与条款原文冲突的方案题，验收回答点名该条款，并写明因此不能采用。
- **SC-004**: 方案题在四项关键条件未齐之前，验收回答不出现最终推荐方法。
- **SC-005**: 声纳限制和检查井先后，只有原文写明时才出现肯定句；抽查不得出现原文没有的百分数。

## Assumptions

- 比较、方案和解释题的验收题面以现有九题文字为准，不另增业务场景。
- 「人员进入」「人工下井」视为同一种检测方法的不同说法。
- 缺失项清单以需求中的方案题为准：积泥是否埋没探头、流速、管段长度、有无竣工资料。
- 数值界限只从本轮检索到的原文读取，不把未检索到的百分数写进程序结论。
- 本切片不发布新的 RI/MI 规则，也不改写已有计算追问行为。
- 阶段规格 `specs/02-requirements/product-requirements.md` 与治理章程仍然有效；若冲突，先改规格再改行为。
