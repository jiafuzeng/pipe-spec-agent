# 技术设计

## 1. 技术选型

| 层次 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.11+ | 计算、绘图、MCP 和 Web 在同一语言里测试 |
| Web | FastAPI，单页聊天界面 | 现场演示需要会话、日志和图片，不需要多页应用 |
| 工具层 | 独立进程的 MCP 服务（FastMCP，Streamable HTTP） | 任务要求工具经 MCP 调用，调用记录与 Agent 进程分离 |
| 检索 | 条款 JSONL + BM25 + 本地向量索引 + reranker | 关键词与语义双路候选合并去重后由 reranker 重排，返回可追溯证据；索引可本地构建，不依赖独立向量服务 |
| 模型 | OpenAI 兼容 HTTP 接口，地址和密钥放在环境变量 | 模型只做意图、槽位抽取、规划和行文。换模型不改计算 |
| 数值 | `decimal.Decimal` | 等级边界用精确值比较 |
| 绘图 | Matplotlib 输出 PNG | 图片由工具生成，界面直接显示 |
| 测试 | pytest | 计算、槽位和检索在接入模型之前就有确定结果 |

不把公式写进提示词后让模型运算。提示词只描述何时调用哪个工具。

## 2. 进程与模块

```
浏览器
  └─ Web（FastAPI）
       ├─ 会话槽位（按 session_id 存在内存，演示足够）
       ├─ 编排器
       │    ├─ 意图识别
       │    ├─ 槽位检查
       │    ├─ 规划
       │    ├─ 检索
       │    └─ 回答组装
       └─ MCP 客户端
            └─ MCP 服务（另一进程）
                 ├─ 缺陷分值
                 ├─ K / E / T 查表
                 ├─ 结构性 / 功能性计算
                 ├─ RI / MI
                 └─ 曲线图
```

知识文件：

```
kb/clauses.jsonl     # 一条条款一行：clause_id, text, page
kb/tables/*.yaml     # 人工核对后的分值表和参数表
kb/index/            # BM25 与向量索引；记录语料、分块和 embedding 模型版本
```

代码目录在实现阶段按这个边界建立，不把查表逻辑复制进编排器。

## 3. 一轮对话

编排器对每一轮按下面的顺序执行，并在执行过程中写入规划日志。

1. **意图。** 判为条文、对比、方案、计算、绘图或追问后的补参。一句话里既要解释又要计算时，拆成先后两步，计算步仍受槽位约束。
2. **槽位。** 计算或绘图意图先合并本轮新参数和会话中已确认参数。必填项缺一则生成追问清单，规划在此结束，不调用计算器。
3. **规划。** 写出即将执行的步骤：检索哪些主题、调用哪些工具、工具参数从哪个槽位来。
4. **执行。** 按计划调用检索或 MCP。工具返回错误则停止后续计算步骤，把错误展示给用户。
5. **组装。** 条文题只使用本次检索到的条款。计算题只引用本次工具返回的数字，并附上工具给出的条款号。绘图题把 PNG 放入回答。
6. **核对。** 组装后的数字若有不在工具返回中的，删去该数字并改为说明本次未能核对。

规划日志和 MCP 日志随回答一起返回给界面。日志结构见 `04-interfaces.md`。

## 4. 检索

建库步骤单独作为任务，不在回答时临时 OCR。

1. 扫描页 OCR 成文本，按条款号切分。条款号形态为 `1.0.1`、`4.1.1`、`8.3.2` 这类编号。
2. 表单独成块，块号使用表号，例如 `表8.3.4-1`。表的机器可读版本以 YAML 为准，文本块用于引用原文位置。
3. 按规程版本、章节、内容类型等元数据过滤；条款号/表号查询优先精确匹配。普通自然语言查询并行执行 BM25 关键词召回和向量语义召回。
4. 合并 BM25 与向量召回的候选并按证据 ID 去重，再由 reranker 按查询与候选证据的相关性重排，截取最终 top-k。条款号/表号精确命中保留优先级。返回条款号、原文片段、页码、各路分数、命中来源和最终名次。
5. embedding/reranker 模型、各路候选数量、最终 top-k 和证据阈值通过标注查询集评估确定。
6. 编排器把最终证据交给模型组织句子。模型不得引用未命中的条款号。没有可用命中时使用章程中的固定语句。

BM25 与向量索引只包含 `approved` 内容，并与来源版本、分块规则和 embedding 模型版本绑定；任一变更时重建索引。混合召回的分数不是法规依据，只有通过审核的原文证据可以进入回答。

结构性缺陷分值、K、E、T、等级阈值不走「让模型从 OCR 文本里读数字」，走 YAML 查表工具，避免水印导致 OCR 串值。YAML 的核对是 T1 的完成条件。

## 5. 智能问数与记忆

槽位是结构化字段，不是一段自由摘要。字段定义、必填组合和追问文案的数据来源见 `04-interfaces.md`。

抽取由模型完成，结果必须通过模式校验：管径是正数，K 只能是 0、3、6、10，T 只能是表 8.3.4-3 中出现的值，缺陷必须带名称或代码以及等级或分值。校验失败则忽略该字段并继续追问，不把模糊词写成一个数。

「流砂」这类表中不存在的土质名称，记录为未匹配，并向用户展示表中的列名。不写入 T。

界面用标签显示已确认槽位。用户说「把管径改成 800」时只替换管径，并清除由旧管径推出的 E，下次计算时重新查表。

## 6. 方案规划

方案题的规划步骤固定为：

1. 检索候选方法的约束条款（电视、潜望镜、声纳、人员进入、潜水、检查井先后、联合检测）。
2. 把用户已给事实填进约束：管径、水位或充满度、水深、能否降水、积泥。
3. 对每条「不得 / 应 / 不宜」给出满足、不满足或信息不足。
4. 信息不足且会改变「满足 / 不满足」时，先追问。
5. 在已确定的约束下安排顺序：检查井在管道检测之前（第 9.0.1 条）；一种方法不能反映全面状况时采用联合检测（第 3.0.3 条）；声纳轮廓图不作为结构性缺陷的最终依据（第 5.4.5 条）。

不输出规程没有的设备型号和停水时限。

## 7. 失败处理

| 情况 | 行为 |
| --- | --- |
| MCP 超时或连接失败 | 重试一次。仍失败则告诉用户工具不可用，本轮不给计算结论 |
| 工具参数校验失败 | 把工具返回的缺失或非法字段转成追问 |
| 查表未命中 | 返回候选行，由用户选定。不取最相近的一行 |
| 检索无命中 | 固定拒绝语句 |
| 模型输出了工具结果中没有的数字 | 删去该数字，保留已核对部分 |

这些行为写进自查说明的「失败策略」一节，并在测试里至少覆盖超时和未命中各一次。

## 8. 界面

单页三区：对话、规划与 MCP 日志、当前槽位。计算得到的 PNG 显示在对应回答下方，并提供原图链接。演示分辨率以笔记本浏览器全屏为准。

界面不提供「关闭日志」的开关。
