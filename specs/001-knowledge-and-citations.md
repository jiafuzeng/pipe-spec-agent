# 001 知识来源、检索与引用

状态：Draft  
范围：唯一知识源、文档处理、条款检索、证据引用、无依据拒答。

## 目标

系统只能把经核验的《CJJ 181—2012 城镇排水管道检测与评估技术规程》内容作为规程事实依据。回答中的条款号必须来自检索返回，不由模型生成。任务要求的“无相关规定”统一话术为：**依据 CJJ 181—2012 原文无相关规定，不作推测性补充。**

## 术语

- **来源版本**：原始 PDF 的 SHA-256、版次和导入时间。
- **条款证据**：至少包含条款号、原文片段、印刷页码、PDF 页序、审核状态和来源版本。
- **已核验内容**：人工对照原始 PDF 后标记为 `approved` 的文本、表格或公式。
- **不足证据**：没有直接支持结论的条款，或召回内容无法确认用户所问条件。

## 功能需求

### KN-01 单一来源

检索 API 只接受指定规程版本的已核验资料。禁止开放域网络搜索、外部百科和非该 PDF 资料参与回答。对于库外问题，系统不得以通用知识补足。

### KN-02 条款级证据

导入时保留 PDF 页序和印刷页码，优先按章节、条款、表格单元或公式切分。条款记录包含来源哈希、章节、条款号、标题、原文、内容类型和审核状态。OCR 结果不能自动视为已核验。

### KN-03 可追溯回答

所有规程事实、计算依据和结论均引用至少一条证据。引用条款号必须存在于本次检索结果中；对表格引用应保留表号和适用行列/条件。界面可展开证据原文并显示 PDF 页码。

### KN-04 不足证据处理

若没有相关条文，或检索到的条文无法回答用户指定条件，回复统一拒答文本；必要时补充说明缺失的是哪一类证据，但不得给出推测性补充。不得用低置信近似命中强行作答。

### KN-05 对比回答

比较类问题按照用户指定维度逐项呈现，至少包含各方法/对象、差异、依据和明确结论。不能只拼接条文摘录；“建议”须标明为基于已知条件的系统分析，并与原文规定区分。

### KN-06 混合检索

自然语言查询并行执行 BM25 关键词召回与向量语义召回，将两路候选合并并按证据 ID 去重，再由 reranker 按查询与候选证据的相关性重排并截取最终结果；条款号/表号查询优先精确匹配。索引仅包含已核验内容，并与来源版本、分块规则和 embedding 模型版本绑定。具体 embedding/reranker 模型、各路候选数量、最终 top-k 及证据阈值通过标注查询集评估确定。

混合检索返回的仍是原文证据。检索分数和排序不能单独作为作答依据；相关度不足、证据冲突或内容不支持结论时，必须澄清或拒答。

### KN-07 来源元数据和审核门禁

每个索引 node 必须关联不可变的来源文档版本：原始文件名、原文 SHA-256、版次、PDF 页序、审核状态；存在 DocMind layout 时保留 layout ID/index/type。导入和向量化成功不能自动把内容标为已核验；新版本默认 `pending_review`，召回必须过滤为 `approved`。Web 导入、切片、embedding 和 Chroma 元数据契约见 `006-rag-ingestion-v1.md`。

## 接口契约（逻辑）

```json
{
  "query": "string",
  "filters": {"chapter": "string|null", "clause_no": "string|null", "content_type": "string|null"},
  "top_k": "integer"
}
```

响应是 `evidence[]`，每项含 `clause_no`、`chapter`、`page_printed`、`page_pdf`、`quote`、`content_type`、`source_hash`、`review_status`、`bm25_score`、`vector_score`、`reranker_score`、`rank` 和 `retrieval_sources`。只允许 `approved` 项传入回答生成步骤；分数和名次用于检索审计，不作为规程事实依据。

## 验收场景

### KN-01-A 规程范围内的问题带引用

**Given** 相关条款已核验并入库。  
**When** 用户询问 CJJ 181—2012 的编制目的与适用范围。  
**Then** 回答逐项覆盖问题，并展示支持各项结论的真实条款号和证据片段。

### KN-02-A 库外问题不补充

**Given** 检索库没有支持用户问题的规程内容。  
**When** 用户询问 PDF 未涉及的规范、法规或经验建议。  
**Then** 输出统一拒答话术，不引用无关条款，不进行外部检索或通用知识补全。

### KN-03-A 不伪造条款号

**Given** 模型草稿含有检索结果中不存在的条款号。  
**When** 输出校验执行。  
**Then** 回答被阻断并重写为基于证据的答案或拒答；伪造条款不会展示给用户。

### KN-04-A 五种检测方法对比

**Given** CCTV、QV、声纳、人工下井、潜水的相关原文已核验。  
**When** 用户要求按管径/水位、缺陷类型、效率/安全、现场配合四维比较。  
**Then** 页面展示四维对比并给出适用条件下的选择结论，每项结论可回溯到规程依据；没有原文支持的维度按统一拒答规则处理。

### KN-05-A OCR 未核验条目不可引用

**Given** 某公式或表格仅有 OCR 草稿而审核状态不是 `approved`。  
**When** 用户询问该公式或参数。  
**Then** 该 OCR 项不会用于生成答案或计算，系统提示当前无法从已核验资料中确认。

### KN-06-A 混合检索召回

**Given** 已核验条款已建立 BM25 索引和向量索引。  
**When** 用户用条款原词、同义表达或语义改写提出查询。  
**Then** 系统并行执行关键词与语义召回，将两路候选合并去重后由 reranker 重排，再返回最终证据；每条证据包含真实条款号、原文片段、页码和来源版本。索引只包含 `approved` 内容，精确条款号/表号查询保留优先级。

### KN-06-B 混合检索不可替代证据核验

**Given** 融合结果相关度不足、两路结果冲突或候选原文不支持用户问题。  
**When** 回答生成前进行证据充分性检查。  
**Then** 系统追问或按固定话术拒答，不因候选排名靠前而引用无关条款或补充规程外内容。

## 非功能要求

- 同一问题在固定来源版本、检索配置和模型版本下应可审计和复现。
- 证据内容应可从答案一键查看；日志记录来源版本和证据 ID。
- 入库与发布流程可回滚到上一已核验版本。

## 未决项

- 原 PDF 的印刷页码与 PDF 页序映射规则。
- 文档是否允许将规程全文持久化到本地向量索引，以及页面截图在演示中的展示方式。
- Embedding/reranker 模型、各路候选数量、最终 top-k 和证据阈值须通过人工标注样例评估后确定，不能在未评估前写死。
